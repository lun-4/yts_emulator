# DMNware App Generation — Authoring Guide

Reference for writing new tablet apps as code that the editor compiles into a UGUI prefab. Audience: humans, and AI agents that need to produce a new DMNware app in one shot.

---

## Status

**This is a forward-looking design spec.** As of writing, the codegen system described here does not exist yet. The DSL types, theme asset, asset registry, codegen menu, and validation pipeline all need to be built. Existing DMNware apps under `Assets/nat/UdonScripts/DMNware/` are out of scope for this system and remain hand-authored.

Open verification items still to spike during implementation:
- Persistent `UnityEvent` listeners (`UnityEventTools.AddPersistentListener`) targeting an `UdonBehaviour` method actually invoke at runtime in a Udon world build, not only in editor.
- The exact serialized field names on `DmnwareUIInteractable` survive a prefab rebuild (vs. being reset by `PrefabUtility.SaveAsPrefabAsset`).

These do not block writing apps against this guide; they block the codegen implementation.

---

## When to use this system

Use it for **new apps** where prototyping speed matters more than pixel-perfect design. The contract is:

- One-shot generation: write code, run a menu item, get a prefab.
- Output is plain UGUI; finger touch and laser interaction work via the existing `DmnwareUIInteractable` pipeline.
- Apps are **shippable** as-is, or can be **ejected** later for hand-tuning.

Do **not** use for:
- Modifying any existing DMNware app (Smart Home, Tutorial, Camera, Chat, etc.). The codegen never sees them.
- Apps that need a custom Canvas, world-space positioning, or non-UGUI rendering.
- Anything that needs runtime UI tree mutation (the tree is fixed at codegen time; you toggle visibility/state on existing nodes).

## File layout per app

For an app named `MyApp`, four files live in `Assets/nat/UdonScripts/DMNware/Apps/Gen/MyApp/`:

| File | Author | Purpose |
|---|---|---|
| `MyApp.layout.cs` | You | DSL tree describing the UI. Editor-only (`#if UNITY_EDITOR`). |
| `MyApp.cs` | You | `UdonSharpBehaviour` partial. Lifecycle methods + handler methods. |
| `MyApp.gen.cs` | Generator | `partial` of `MyApp` with `[SerializeField]` fields for every interactive id. |
| `MyApp.prefab` | Generator | Two-GameObject prefab: `DmnwareApp` metadata + container with the U# behaviour and the UI tree. |

The `.layout.cs` file is the source of truth. Deleting it ejects the app (see [Eject](#eject)).

## The two files you write

### `MyApp.layout.cs`

```csharp
#if UNITY_EDITOR
using DMNware.AppGen;

[DmnwareApp(
    name: "Counter",
    iconKey: "counter",     // resolved against DmnwareAppGenAssets registry
    handheldOnly: false,
    vrOnly: false
)]
public class CounterLayout : AppLayout
{
    public override Node Build() => Vertical(
        padding: Spacing.LG,
        spacing: Spacing.MD,
        Header("Counter"),
        Text(id: "count", text: "0"),
        Spacer.Flex(),
        Horizontal(spacing: Spacing.SM,
            Button("dec", "−",     nameof(Counter._OnDecrement)),
            Button("inc", "+",     nameof(Counter._OnIncrement)),
            Button("reset", "Reset", nameof(Counter._OnReset)).Style(Variant.Danger)
        )
    );
}
#endif
```

### `MyApp.cs`

```csharp
using UdonSharp;
using UnityEngine;
using UnityEngine.UI;
using TMPro;

public partial class Counter : UdonSharpBehaviour
{
    [HideInInspector] public DmnwareDevice Device;  // injected by Device on init
    [HideInInspector] public DmnwareApp App;         // injected by Device on init

    private int _value = 0;

    // Lifecycle
    public void _DmnwareAppInit()     { _Refresh(); }
    public void _DmnwareAppLateInit() { }
    public void _DmnwareAppOpen()     { }
    public void _DmnwareAppClose()    { }

    // Handlers
    public void _OnIncrement() { _value++; _Refresh(); }
    public void _OnDecrement() { _value--; _Refresh(); }
    public void _OnReset()     { _value = 0; _Refresh(); }

    private void _Refresh()
    {
        // `count` is generated as a [SerializeField] TMP_Text in MyApp.gen.cs
        count.text = _value.ToString();
    }
}
```

### Generated `MyApp.gen.cs` (do not hand-edit)

```csharp
// <auto-generated />
using UnityEngine;
using UnityEngine.UI;
using TMPro;

public partial class Counter
{
    [SerializeField] private TMP_Text count;
    [SerializeField] private Button dec;
    [SerializeField] private Button inc;
    [SerializeField] private Button reset;
}
```

## Lifecycle contract

The `DmnwareDevice` calls these on the U# behaviour via `SendCustomEvent`. All are parameterless. Implement only the ones you need (empty bodies for the rest).

| Method | When | Notes |
|---|---|---|
| `_DmnwareAppInit` | Once at world start, before any app opens. | Cache references, set initial UI state. UI tree exists at this point. |
| `_DmnwareAppLateInit` | Once at world start, after every app's `_DmnwareAppInit`. | Cross-app dependencies. |
| `_DmnwareAppOpen` | Each time the user opens this app. | App container is now reparented under the visible tablet area. |
| `_DmnwareAppClose` | Each time the user leaves this app. | Save state if needed. |
| `_DmnwareAppHandheldModeChange` | Tablet switches between handheld and pinned modes. | Read `Device.IsCurrentlyHandheld`. |
| `_DmnwareAppOrientationChange` | Tablet rotates. | Read `Device.IsCurrentlyLandscape` / `Device.IsCurrentlyLandscapeU`. |
| `_DmnwareAppPickupTrigger` | Tablet pickup trigger fired (right-click while held). | |
| `_DmnwareAppDirtyApps` | App roster changed (notification badges, etc.). | |

`Device` and `App` are injected by `DmnwareDevice` before any of these fire. Don't set them yourself.

## DSL reference (v1)

### Containers

```csharp
Vertical(padding?, spacing?, align?, justify?, params Node[] children)
Horizontal(padding?, spacing?, align?, justify?, params Node[] children)
```
- `padding`: `Spacing.XS|SM|MD|LG|XL`, a number, or `(l,t,r,b)` tuple.
- `spacing`: gap between children. Same types.
- `align`: `Align.Start | Center | End | Stretch` (cross-axis).
- `justify`: `Justify.Start | Center | End | SpaceBetween | SpaceAround` (main-axis).

Containers map to `VerticalLayoutGroup`/`HorizontalLayoutGroup` + `ContentSizeFitter`. Use `Spacer.Flex()` to push siblings apart along the main axis.

### Leaves

```csharp
Text(string text, Typography style = Typography.Body)
Text(id: string, text: string, style: Typography = Body)   // give it an id only if your code updates it
Header(string text)                                         // shorthand for Text(..., Typography.Header)
Image(string assetKey, FillMode mode = FillMode.Contain)
Image(id: string, assetKey: string, mode: FillMode = Contain)
Spacer.Fixed(float width, float height)
Spacer.Flex(float weight = 1f)
Divider(Orientation o = Orientation.Horizontal)
```

### Interactives

```csharp
Button(string id, string label, string onClick)
IconButton(string id, string iconKey, string onClick)        // v2 — not in v1 surface
Toggle(string id, string label, bool init, string onChange)
Slider(string id, string label, float min, float max, float init, string onChange, bool integer = false)
```

`onClick`/`onChange` arguments must be `nameof(MyApp._SomeMethod)`. The codegen validates the method exists.

### Modifiers

Fluent methods on any `Node`:

```csharp
.Width(float | Size.Auto | Size.Flex(weight))
.Height(float | Size.Auto | Size.Flex(weight))
.MinWidth(float)  .MaxWidth(float)
.MinHeight(float) .MaxHeight(float)
.Padding(...)     // same overloads as container `padding`
.Margin(...)
.Flex(float weight = 1f)             // shorthand inside V/H containers
.Style(Variant v)                     // Primary | Secondary | Ghost | Danger
.Hidden(bool initiallyHidden = true)  // toggle GameObject.SetActive at runtime via the SerializeField ref
```

### Escape hatch

```csharp
Raw(string prefabKey, string id)
```

Drops a registered prefab into the tree. The id exposes the spawned `GameObject` in the partial class. Use only when a primitive doesn't fit. Don't use for anything that already has a primitive.

## Wiring contract

### Ids

- Must be a valid C# identifier (`[A-Za-z_][A-Za-z0-9_]*`).
- Unique per layout. Duplicates are a hard error.
- Becomes the field name on the partial class. Pick names you'd be happy reading in `MyApp.cs`.
- Lower camelCase recommended (`brightness`, `confirmBtn`, `playerList`).
- Reserved (codegen rejects): `Device`, `App`, `transform`, `gameObject`, `enabled`, `name`, `tag`, `layer`, anything starting with `_dmnware`.

### Generated field types per primitive

| Primitive | Field type |
|---|---|
| `Text` (with id) | `TMP_Text` |
| `Image` (with id) | `Image` |
| `Button` | `Button` |
| `Toggle` | `Toggle` |
| `Slider` | `Slider` |
| `Raw` | `GameObject` |

Containers and leaves without ids are not exposed as fields.

### Handler signatures

Always **parameterless**. Read the control's current state directly:

```csharp
public void _OnBrightnessChanged() {
    float v = brightness.value;     // from Slider field
    /* ... */
}

public void _OnFunnyToggled() {
    bool v = funny.isOn;            // from Toggle field
    /* ... */
}
```

This is a Udon constraint: `SendCustomEvent` does not pass arguments. The codegen wires both the standard UGUI event (`Slider.onValueChanged`, `Toggle.onValueChanged`, `Button.onClick`) **and** the `DmnwareUIInteractable.MethodName` to the same handler, so finger and laser both work.

## Theming

A single `DmnwareTheme.asset` ScriptableObject defines the look. Apps don't reference it directly — the codegen reads it and bakes concrete colors / sprites / fonts into prefabs.

Theme contains:

| Section | Fields |
|---|---|
| Palette | `Background`, `Surface`, `SurfaceElevated`, `Primary`, `OnPrimary`, `Text`, `TextMuted`, `Accent`, `Danger`, `OnDanger` |
| Typography | `Header`, `Body`, `Caption` — each `(TMP_FontAsset, size, weight, color)` |
| Spacing | `XS=4, SM=8, MD=12, LG=20, XL=32` |
| Sprites | `ButtonBg`, `ButtonBgPrimary`, `ButtonBgDanger`, `InputBg`, `PanelBg`, `SliderTrack`, `SliderFill`, `SliderHandle`, `ToggleBg`, `ToggleKnob` |
| Defaults | Button height, slider thumb size, scrollbar width, corner radius set |

Variants applied via `.Style(...)`:

| Variant | Effect on Button |
|---|---|
| (default) | `ButtonBg`, `Text` color |
| `Primary` | `ButtonBgPrimary`, `OnPrimary` |
| `Secondary` | `ButtonBg` with `Accent` text |
| `Ghost` | transparent bg, `Text` color |
| `Danger` | `ButtonBgDanger`, `OnDanger` |

Theme edits require running `DMNware ▸ Regenerate All` to propagate.

## Asset registry

`DmnwareAppGenAssets.asset` is a tiny ScriptableObject with two named maps:

```
icons:    string -> Sprite
prefabs:  string -> GameObject     (for Raw())
```

Layouts reference assets by **string key only**. Unknown keys fail the generator with a list of valid keys.

To add an asset: open the registry, drag the sprite/prefab in, give it a key. Keys are kebab-case (`smart-home`, `chat-bubble`, `power-icon`).

This protects AI authors from inventing nonexistent paths or guessing GUIDs.

## Scene-context references

The codegen needs two project-wide things to wire interactives:

| Thing | Purpose |
|---|---|
| Click `AudioSource` | Played by `DmnwareUIInteractable` on tap. Existing tablet shared sound. |
| `DmnwareDevicePickupCustomization` | Used by interactables that activate input fields, to force-drop the tablet. |

These live in `DmnwareAppGenContext.asset`. Set once during codegen system setup. Apps never reference them.

## Codegen invocation

| Action | Command |
|---|---|
| Regenerate one app | Right-click `MyApp.layout.cs` in Project ▸ **Generate UI for this app** |
| Regenerate all apps | Menu ▸ **DMNware ▸ Generate App UI** |
| Theme-changed regen | Menu ▸ **DMNware ▸ Regenerate All (theme changed)** (alias) |

Output is idempotent — re-running with no changes does not dirty git.

After generating a brand-new app for the first time: drop the prefab under the tablet's `AppSource` transform once. After that, regeneration only edits the prefab in place; the scene reference is stable.

## Validation

The generator hard-fails (no partial output) on:

1. Duplicate ids within one layout.
2. Reserved id name.
3. `nameof(MyApp._X)` references a method that doesn't exist on the partial U# class.
4. `[DmnwareApp]` attribute missing required fields.
5. Asset key not in `DmnwareAppGenAssets`.
6. `Build()` returns null or an empty container.
7. Layout file has no matching `<Name>.cs` U# behaviour file.

Console output is one line per app: `generated`, `skipped`, or `errored: <reason>`. Errors include suggestions where applicable (`unknown asset key "smart_home" — did you mean "smart-home"?`).

## Eject

To remove an app from codegen control: **delete `MyApp.layout.cs`**.

That's the entire mechanism. Effects:
- The codegen no longer regenerates `MyApp.gen.cs` or `MyApp.prefab`.
- Both files become normal hand-edited project files.
- The U# behaviour `MyApp.cs` keeps working unchanged — it's still a partial, just now without a generated half. You'll need to manually merge the field declarations from `MyApp.gen.cs` into `MyApp.cs` (or leave `.gen.cs` in place and stop calling it generated).

To re-include in codegen: recreate `MyApp.layout.cs`. The next generation overwrites the prefab to match.

## Things not to do

- **Don't put logic in `Build()`.** It runs once at codegen time. No `if`-on-runtime-state, no reading scene refs, no instantiation.
- **Don't add fields to the partial that the layout already declares.** The codegen owns those names; collision is a build error.
- **Don't reference Unity primitives directly from the layout** (no `Vector3`, `Quaternion`, `Instantiate`, `transform.Find`). The DSL is a description, not imperative code.
- **Don't take parameters in handler methods.** `SendCustomEvent` is parameterless in Udon. Read state from the control's serialized reference.
- **Don't manually edit generated files.** They have a `<auto-generated />` header; regen will overwrite. Eject first.
- **Don't add a Canvas to the app prefab.** The tablet provides one; the app root is a `RectTransform` only.
- **Don't set transform position/rotation/scale on the app root in `Build()` or in any lifecycle method.** `DmnwareDevice._OpenAppByIdx` resets these every open.
- **Don't add UI Toolkit (`UIDocument`, `.uxml`, `.uss`).** Not supported in Udon at runtime. UGUI only.

## Minimal new-app checklist

1. Create folder `Assets/nat/UdonScripts/DMNware/Apps/Gen/MyApp/`.
2. Add asset to `DmnwareAppGenAssets` if you need a custom icon.
3. Write `MyApp.layout.cs` (the DSL tree + `[DmnwareApp]` attribute).
4. Write `MyApp.cs` (the U# `partial class` with lifecycle + handlers).
5. Run `DMNware ▸ Generate App UI`.
6. First time only: drag `MyApp.prefab` under the tablet's `AppSource` transform.
7. Open Unity Play / VRChat ClientSim; confirm the app shows up on the home screen and reacts to taps.

## v2 candidates (not in initial generator)

For future expansion, in rough priority order:

- `Grid(int cols, ...)` — `GridLayoutGroup`-backed.
- `Scroll(direction, ...)` — `ScrollRect` with viewport + content + scrollbar; integrates with `DmnwareUIInteractable`'s `SupportDragging`.
- `Input(string id, string placeholder, string onSubmit)` — wraps `InputField`.
- `IconButton(...)`.
- `NotificationBuilder` — declarative version of `_LaunchNotificationFromApp`.
- `AppIconBuilder` — declarative home-screen entry styling.
- `Stack(...)` — z-overlay container.
- Theme variants beyond the default four.
